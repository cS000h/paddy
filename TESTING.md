# 测试说明

这张表就是测试清单本身：`tools/test.mjs` 按表执行，不在表里的测试文件不会被运行，
而 L0 的登记检查会因此报错。所以**加测试必须在下面的表里加一行**。

## 怎么跑

| 命令                              | 跑什么                                           |
| --------------------------------- | ------------------------------------------------ |
| `npm test`                        | 带 `fast` 标签的全部测试，几秒钟，每次改动后都跑 |
| `npm run test:all`                | 表里的全部测试，含格式、类型和浏览器             |
| `npm run test:browser`            | 只跑 L5（需要本机装有 Chrome）                   |
| `node tools/test.mjs --level L2`  | 只跑某一层，多层用逗号隔开                       |
| `node tools/test.mjs --scope sim` | 只跑某个范围                                     |
| `node tools/test.mjs --tag save`  | 只跑带某个标签的                                 |
| `npm run test:list`               | 列出清单，不执行                                 |

## 层级

越往下越慢、越接近玩家看到的东西；越往上越快、越能指出是哪一行错了。
一个问题应该在能抓住它的最上面一层写测试。

| 层级 | 名称     | 回答的问题                                     | 怎么写                                       |
| ---- | -------- | ---------------------------------------------- | -------------------------------------------- |
| L0   | 静态检查 | 结构还守规矩吗？分层、登记、格式、类型         | 只读文件，不运行游戏                         |
| L1   | 单元     | 这一个零件自己对吗？内核、数据、纯函数         | 不经过端口，直接调用被测的模块               |
| L2   | 规则     | 这条玩法规则对吗？                             | 只通过端口发命令、问查询；写入检查开着       |
| L3   | 契约     | 外壳依赖的接口变了吗？旧存档还读得了吗？       | 清单对比、样本存档                           |
| L4   | 回放     | 乱玩很多步会不会坏？行为有没有在不知情时变了？ | 固定种子的随机玩家、最终世界的指纹           |
| L5   | 浏览器   | 真的在浏览器里跑得起来、走得动、种得下吗？     | 无界面的 Chrome 打开构建结果                 |
| L6   | 人工验收 | 好看吗？手感对吗？想不想接着玩？               | 不自动化，按本文末尾的清单试玩，结论写进提交 |

## 字段

- **编号**：`层级-两位序号`，只增不改，删掉的编号不再复用。
- **范围**（scope）：被测的是哪一块，取值为 `repo`、`kernel`、`content`、`sim`、`port`、`art`、`world`、`panels`、`app`。
- **标签**（tags）：用空格隔开。`fast` 和 `slow` 必须二选一。
  其余可选：`static`、`unit`、`rules`、`contract`、`save`、`replay`、`golden`、`browser`。
  - `golden` 表示里面有“基线”：行为有意改变时，要按测试的提示更新基线值。
  - `save` 表示和存档格式有关：改了世界的数据结构就要看它。

## 加一个测试的步骤

1. 想清楚它属于哪一层：能在 L1 抓住的就不要写到 L2，能在 L2 抓住的就不要写到 L5。
2. 把文件放进 `tests/<层级>-…/`，文件名以 `.test.js` 结尾。
3. 在上面的清单里加一行，编号取这一层的下一个序号。
4. 运行 `npm test`。登记不对会由 L0-01 指出来。

## L6 人工验收清单

每次改了画面或手感，按下面的问题试玩几分钟，把结论写进提交说明。

| 维度     | 观察的问题                                                                         |
| -------- | ---------------------------------------------------------------------------------- |
| 第一眼   | 能否认出是中式田园？清新但不苍白？                                                 |
| 空间     | 能否判断哪里能走、哪里能进、哪里能互动？                                           |
| 操作     | 是否容易对准目标？动作反馈是否及时、明确？                                         |
| 农事     | 作物状态是否一眼可见？重复操作是否有满足感？                                       |
| 人物     | 是否记住了某个村民在做什么，而不只是他的功能？                                     |
| 设备     | 键鼠和触屏是否都能不看说明完成锄地、播种、浇水？手机竖着、横着拿是否都是横屏画面？ |
| 节奏     | 是否有自主安排的余地，而不是被催着走？                                             |
| 长期动机 | 是否自然产生“明天还想做什么”？                                                     |
